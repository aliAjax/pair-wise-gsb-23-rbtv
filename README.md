# hxwl-09 半导体洁净室巡检

洁净等级阈值版本化判定、粒子计数与异常处理、复核锁定、乐观锁并发冲突与可恢复草稿的巡检系统。

## 技术栈

React 19 + Vite + TypeScript + CSS（无后端，数据持久化在浏览器 localStorage，跨标签页通过 `storage` 事件同步）

## 本地运行

```bash
npm install
npm run dev      # http://localhost:5109
npm run build    # 类型检查 + 生产构建
```

## 业务规则

- **新建巡检按当班阈值版本判定**：以“生效时间 ≤ 当前时刻”的最新一版为准，提交时把版本号与该等级阈值**快照**写进记录。
- **发布新阈值只影响之后的新记录**：历史记录永远按原版本的快照展示判定，不被新版本追溯改写；驳回后重提也沿用原版本。
- **复核锁定**：厂务工程师复核通过后记录锁定，任何角色都不能再改；驳回后巡检员可修改重提。
- **等于上限即异常**：测量值 `≥ 上限` 或 `≤ 下限` 判异常；进入阈值宽度 10% 的边缘带判关注；设备故障直接判异常。
- **乐观锁并发控制**：每条记录带 `revision`。两人同时编辑同一记录时，晚提交的一方收到版本冲突——对方刚保存的结果**不会被覆盖**，自己的输入原样保留为“冲突草稿”，可逐字段对比合并后基于新版本再保存。
- **中途关闭可恢复**：输入停顿 500ms 自动保存草稿（新建/编辑/冲突三类）；已提交记录与审计轨迹同样持久化，重开页面全部恢复。
- **导出摘要**：CSV 每行带「记录版本 vN」和「阈值版本 vX」，并含阈值生效时间与判定口径说明。

## 页面

1. **巡检记录**：动态看板、草稿恢复条、等级/状态筛选、记录展开（各测量值判定理由 + 阈值快照 + 复核信息）、新建/编辑/复核、CSV 导出。
2. **阈值版本**：查看全部历史版本与当班版本；厂务工程师可发布新版本（只追加、不可改旧版）。
3. **审计轨迹**：提交/保存/冲突/复核/阈值发布等全部事件，带操作人、时间、记录版本与阈值版本标签。

## 并发冲突演示

- 方式一：展开任意待复核记录 → 点「模拟他人先保存 vN+1」→ 再点「编辑」修改后保存，即看到冲突横幅、草稿保留与逐字段合并面板。
- 方式二：开两个浏览器标签页同时编辑同一记录（跨标签页实时同步），后保存的一方真实触发冲突。

## 种子数据

预置 v1.0（2026-01-01 生效）与 v2.0（2026-07-01 生效，湿度/压差收紧）两个阈值版本和 4 条记录，其中：

- v1 时期的 ISO 5 异常记录在 v2 发布后仍按 v1 显示异常；
- CR-3305 的 0.5μm 粒子数 29300 恰好等于 v2 上限，演示“等于上限判异常”；
- 另有一条未完成草稿，演示重开页面恢复。
